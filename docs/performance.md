## Measurement contract

Single-command entry point:

```sh
./scripts/bench.sh --label local --output /tmp/cadr-performance.json
```

The default parameters are fixed at a 100×40 terminal,
`N ∈ {0, 50, 200, 1000, 5000}`, 1 warm-up and 5 formal samples; the output is
schema version 1 JSON. The formal samples report median and MAD, and every raw
sample is retained.
`--quick` serves development-time smoke only and cannot serve as acceptance
numbers.

Session entries are generated by cycling through a fixed set of five: user
Markdown+CJK/emoji, assistant Markdown, a collapsed read tool block, an
expanded bash tool block, and an image Markdown placeholder+CJK/emoji. There is
no real LLM, network or random input. The hot paths are measured separately:

- `frame_render`: production `render-tui-state → render-frame → virtual-terminal`;
- `key_to_frame`: raw input bytes write out one frame after the input
  decoder/editor;
- `stream_delta_to_frame`: a fixed text delta writes out one frame after agent
  event assembly, and delta/s is reported at the same time;
- `mouse_drag_to_frame`: real SGR press/drag bytes in the alternate screen write
  out one frame after the selection update;
- `wheel_to_frame`: real SGR wheel-up/down bytes in the alternate screen scroll
  in the middle of a long transcript and write out one frame;
- `continuous_alt_input`: 1024 mixed drag and wheel events on a 5000-entry
  transcript, retaining per event the wall latency, allocation, p95/p99/max and
  GC-affected event latency;
- `common_continuous_input`: takes the p95 entry count of the anonymized
  real-session profile as the common tier, splits mouse drag, wheel and editor
  key into three mutually non-diluting 1024-event traces, each retaining its own
  raw latency/allocation samples and enforcing the p99 ≤16ms absolute gate;
- `append_entry`: appends one entry at the tail of a fixed-length history and
  restores the fixture in O(1).

Allocation comes from `sb-ext:get-bytes-consed`; heap occupancy comes from
`sb-kernel:dynamic-usage`; Linux RSS comes from `/proc/self/statm`. Cold start
is started by a standalone Python stdlib PTY harness, which launches the native
`./cadr` in a brand-new temporary `HOME` with no provider credentials in the
environment, times from `Popen` until `cadr v` appears in the first frame, and
then verifies a clean exit with `/quit`. It is "new process to first real TUI
frame", not the weaker `--version` path, and it does not obtain non-portable
fake cold-disk numbers by dropping caches.

The continuous-input measurement temporarily fixes the SBCL nursery at 8MiB
inside an `unwind-protect` and restores the original value on exit. It
deliberately makes the 1024-event run pass through multiple GCs; the
`gc_affected_max_us` in the report is the whole event→frame wall latency the
user actually bears, and `gc_cpu_us` is diagnostic only and never poses as a
precise stop-the-world wall pause.

The complexity label is generated from the log-log slope of the positive-N
points: `<0.35` is constant, `<1.5` is linear, and the rest is
quadratic-or-worse. The label is a regression clue; the gate thresholds will be
fixed in Goal 11 Part E from the post-optimization data and the machine
headroom.

## Fixed TS baseline strategy

The audit target is fixed at `914cf1472` (v0.84.2), not the continuously moving upstream
`main`. The conclusion is unambiguous: pi likewise traverses the complete
component tree every frame and has no viewport-before-render, no virtual
scrolling and no persisted history-prefix frame; its advantage comes from
per-component caching, O(1) append, render-request coalescing, and writing only
changed lines to the terminal.

### Process-start lower bound

The 2026-08-04 same-machine `--version` measurement fills this in as follows.
The stable state is repeated startup after both the file cache and the runtime
artifacts are ready; "first" is the first process start of that round. This
command exits immediately after printing the version and **does not include TUI
initialization, first-frame rendering, configuration discovery or interactive
component construction**; it can serve only as a lower-bound reference for
process startup cost and cannot replace the other real-PTY cold-start numbers in
this document.

Part C therefore adopts only the two mechanisms the baseline already has: adding
a width/content-sensitive rendered-line cache for stable entries, and changing
Lisp list tail insertion into an O(1) append that maintains a tail pointer. It
will not add whole-transcript memoization, viewport pruning or virtual
scrolling; these all go beyond the baseline and, under the global principle,
must go through a separate proposal.

## Optimized results and gates

### Part C — baseline mechanisms restored

The implementation uses only the baseline mechanisms confirmed in Part B:

- `tui-entry` caches the complete rendered lines of stable entries, keyed by
  width, theme object and extension snapshot; streaming, running tool and custom
  tool renderers are not cached. Tool completion, collapse toggling, theme
  change and extension reload all invalidate it. Following Goal 14 B6 the
  implementation lives respectively at
  `src/cadr-cli/interactive/state.lisp:3-34`,
  `entries.lisp:88-95` and `transcript.lisp:812-874`.
- `tui-state` keeps the list tail and the head it belongs to; a normal append
  attaches directly to the tail. The centralized replacement entry point rebuilds
  the tail in step, and if a historical test/fixture does `setf entries`
  directly, the next append performs a single self-repair and does not
  contaminate the old chain. Following Goal 14 B6 the fields live at
  `src/cadr-cli/interactive/state.lisp:36-47` and the centralized
  append/replacement entry point at `entries.lisp:47-86`; production reset still
  goes only through that entry point.

From Part C onward the benchmark's `frame_render` explicitly warms the fixture
once and measures a stable frame; this is a methodological correction that only
becomes meaningful once the cache exists. Before the optimization there was no
rendered-line cache, and a warmed run would still recompute completely; the
archived before numbers therefore remain an equivalent comparison anchor. The
append repetitions were raised at the same time, to keep the O(1) operation from
falling below SBCL's timer resolution.

### Part D — ten-hour deterministic stability run

The entry point `scripts/goal11-stability.sh` uses the production faux provider,
the real agent/session persistence paths, TUI event projection and per-event
virtual-terminal rendering, and at two rounds per minute interprets 1200 rounds
as 10 hours of interaction volume. It forces a full GC at rounds
0/300/600/900/1200 and records heap/RSS, GC pause, FDs and Lisp/OS threads; it
also generates at least 10MiB of real v3 JSONL and, for `load-session`,
`resume-session` and `continue-session` each, records the heap/RSS peak with a
1ms sampler. Complete committed data is in
[`benchmarks/goal-v11-stability.json`](benchmarks/goal-v11-stability.json).

| stability metric | result |
|---|---:|
| faux turns / rendered agent events | 1200 / 14,400 |
| retained heap, turn 0 → 1200 | 35.86MiB → 78.17MiB; exponent 0.966 |
| full-GC pause, turn 0 → max | 52.0ms → 80.0ms |
| FD / Lisp threads / OS threads | 5 / 1 / 2 at every checkpoint and after cleanup |
| post-cleanup heap vs pre-run | -0.09MiB |
| JSONL size / entries | 10,507,435 bytes / 2400 |
| load / resume / continue latency | 328 / 268 / 276ms |
| sampled peak RSS above operation baseline | 99.8 / 98.7 / 98.5MiB |

The growth comes from the 2400 messages/entries still normally referenced by the
agent, the session, the TUI cache and the faux prompt cache; the curve is linear
rather than a leak, and after the whole scenario is released heap, FDs and
threads all return to the baseline. GC pause did not degrade monotonically with
the checkpoints. All three load paths for a 10MiB session are below 0.33s, with
about 73.1MiB retained heap, and no stability defect requiring a change to
observable behavior was found.

The scenario audit instead found that the in-memory append of agent messages and
session entries still uses list `nconc`, which is cumulatively O(N²) just like
the TUI that Part C already fixed. The fixed TS baseline uses
`Agent.state.messages.push()` (`packages/agent/src/agent.ts:541`) and
`SessionManager.fileEntries.push()` (`packages/coding-agent/src/core/session-manager.ts:1044-1048`)
respectively. The same baseline mechanism is therefore carried over, maintaining
a private tail for both; after the public list is replaced wholesale the next
append performs one safety repair. On the old object the agent append exponent
was 0.994 and 21.593µs at N=20000; the new implementation has exponent -0.035
and 0.110µs at N=20000 (196×). Session append is dominated by the roughly 0.1ms
fixed cost of generating a random ID per entry, but at N=20000 it still fell
from 135.394µs to 109.678µs; a structural gate locks the cons tail linkage
directly, so that timing noise cannot mask a regression.

## Performance gates

`scripts/goal11-performance-gate.py` applies a hard gate to the complete
performance/stability JSON.
The thresholds deliberately leave an order of magnitude of headroom for
CI/machine variation, but they still break through this goal's old defects: at
N=5000 frame/key/stream/mouse/wheel must each not exceed 50ms, frame/mouse/wheel
allocation must not exceed 16MiB, and stream must be at least 20 delta/s; the
continuous alternate-screen run must record exactly 1024 events, p99 must not
exceed 150ms, GC-affected max must not exceed 500ms, and when the allocation
crosses the nursery a GC must actually be observed; TUI/agent/session append
exponents must be less than 0.35 and cold start must not exceed 750ms;
1200-turn heap must not exceed 128MiB and its exponent must not exceed 1.30,
full GC must not exceed 500ms, and FD/thread must be constant point by point;
10MiB load/resume/continue must each not exceed 5s, and the sampled heap/RSS
peaks must each not exceed the baseline by 512MiB.

On the same machine a fixed-baseline gate is also applied to the five-round
1024-event traces for mouse, wheel and default GC: the upper bound on
median/p95/p99 is
`max(2 × pi_q, pi_q + max(5ms, 6 × pi_run_MAD_q))`, and max is diagnostic only.
When the candidate machine name is not the archive machine `Friend-MachineD`,
that relative gate explicitly reports
`informational-host-mismatch`; it will not pass off another machine's absolute
microsecond numbers as comparable data. The original 50/150/500ms absolute
budgets still run across machines, but they are equally affected by host
performance and cannot be called host-independent.

### Fifth A/B — continuous alternate-screen input

The old benchmark measured only ordinary frames, keyboard and stream deltas; the
alt-screen tests asserted only scrolling and selection semantics, with no wall
latency, allocation or GC tail for continuous mouse events. All functional
checks could therefore be fully green while real dragging and wheeling still
rescanned every ANSI line in a long document on every frame. This is a missing
gate dimension, not an existing assertion that happened to miss one constant.

The pre-optimization diagnostic obtained by quantifying first was already
unambiguous after running only 8 events at N=5000 with a fixed 8MiB nursery:
median 896.041ms, p99/max 932.060ms, median allocation
202,858,216 bytes/event, and 8/8 events crossing a GC; the default 1024-event
run had still not finished after more than two minutes and was aborted
deliberately, and it cannot be disguised as a complete result.

The fixed baseline is still full document render + viewport slice + changed-row
write, and it is not permitted to take the occasion to introduce virtual
scrolling or transcript memoization. This round eliminates only equivalent
constant costs on the Lisp hot path: stable lines no longer repeatedly construct
reset/copy, scroll/selection no longer force a full clear,
`visible-width` scans the original string directly and is differentially
compared against the old grapheme semantics by property tests, and image prefix
detection changes from two generic substring searches per line to a
same-semantics prefix decision made from the ESC position. The latter has the
same fast/slow prefix semantics as the baseline `isImageLine`, but avoids SBCL's
generic `search` taking up most of a frame on an ordinary ANSI line.

The final committed 1024-event run (HEAD `15bc6ae084d3…`) has completed: at
N=5000 the mouse/wheel medians are both 36.001ms, with allocation
2,832,352/3,668,816 bytes; continuous median 36.001ms, p95 48.001ms, p99
52.001ms, max 68.002ms, and the max over the 447 GC-affected events is 68.002ms.
Relative to the 8-event diagnostic, median
latency fell about 24.9× and
median allocation about 54×; the default scale now runs to completion and
retains all 1024 raw samples. Cold start median 157.428ms (MAD 3.222ms), TUI
append exponent 0.029. The complete JSON is
[`benchmarks/goal-v11-final.json`](benchmarks/goal-v11-final.json), SHA-256
`1d2d3d1faac43006e56b08a505487035c0d8a6dffdc0b52ab069a45c0d0d8f1e`.

## Goal 13 C3 — absolute interaction latency
