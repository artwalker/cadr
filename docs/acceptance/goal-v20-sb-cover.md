# Goal 20 Part N (N2.7) — sb-cover branch coverage measurement

Date: 2026-08-16. SBCL 2.6.7, Linux x86_64.

First full-tree measurement of how much of cadr's own code the FiveAM
suite drives. No coverage threshold is set (draft N2.7 rule 3); the
obligation is a conclusion per zero-coverage branch, not a percentage.

## Reproduction

```sh
./scripts/goal20-cover.sh /tmp/goal20-cover > /tmp/goal20-cover-run.log 2>&1
```

The wrapper mirrors `scripts/test-cl.sh` (isolated `HOME`, fresh
`ASDF_OUTPUT_TRANSLATIONS`, same asd registration and test-system
order) and adds `(optimize sb-cover:store-coverage-data)` plus
`sb-cover:enable-coverage-logging` before anything compiles. One
deliberate deviation from `test-cl.sh`: no `:force t`. Recompiling a
file replaces its per-file coverage record and would drop marks
accumulated by earlier suites; the fresh cache already compiles every
file exactly once with instrumentation.

Artifacts (all under `/tmp/goal20-cover/`, regenerated by the command
above):

- `data.tsv` — per-file branch/expression counts (`C` lines) and every
  never-executed (`Z`) / one-way-only (`P`) branch as file:line +
  enclosing top-level form.
- `coverage.dat` — `sb-cover:save-coverage-in-file` state, restorable
  for re-analysis without rerunning the suite.
- `coverage.lcov` — `sb-cover:lcov-report` output.
- `analyze.tsv` — per-branch records with per-top-level-form "called"
  flags, rebuilt from `coverage.dat` via sb-cover's source-map reader:

  ```sh
  CADR_COVER_ROOT="$PWD" CADR_COVER_OUT=/tmp/goal20-cover \
    sbcl --noinform --script scripts/goal20-cover-analyze.lisp
  ```

## What is measured (honesty clause, policy §6)

A **branch record** is one conditional decision point the compiler
instrumented: the test form of an `if` (including `when`/`unless`/
`cond` clauses and `and`/`or` sub-tests after macroexpansion). Each
branch has two **ways** (:then/:else); coverage below counts ways.
SBCL only instruments a branch when the test form is a cons with a
recorded source path (`best-sub-source-path`, ir1-translators.lisp):
an atomic test like `(if x ...)` yields **no** branch record. The
denominator is therefore "instrumented branches", not "all
conditionals in the source". `cadr-storage`'s 0/0 below is this, not a
failure: its two files contain no conditional forms at all.

Suite completeness: the instrumented run executed exactly the
committed suite — 9 systems, 18,561 checks, 18,561 pass, 0 skip, 0
fail, matching the `GOAL20_TEST_CHECKS` anchor in
`docs/test-matrix.md`. Wall time about 2 minutes (run log birth to
final write).

Line attribution was validated two ways: the compile-time augmentation
locations and an independent rebuild from `coverage.dat` via sb-cover's
source-map reader agree on all 1,488 zero-branch (file, line) pairs,
and the ground-truth calibration file's branch lines match
`lcov-report`'s own `BA:` lines.

### Class B1: untested entries (683 records, 238 top-level forms)

The deterministic suite never calls these functions. The large
clusters, by cause:

- **`cli-handler` and CLI bootstrap** (`src/cadr-cli/bootstrap/commands.lisp`,
  96 records): the process entry is driven only by
  `cadr-cli/live-tests` (credential-gated) and by subprocess smokes
  (`scripts/acceptance-smoke.sh`, `scripts/server-smoke.sh`), neither
  of which is visible to in-image coverage. Biggest single untested
  entry point in the tree.
- **llama extension** (`src/cadr-cli/extensions/llama/{ui,extension}.lisp`
  plus `provider.lisp`, `huggingface.lisp`): 73+ records in the top-10
  files alone. Needs a llama.cpp server and Hugging Face network; no
  deterministic fixture exists.
- **Interactive TUI selectors and components**: config-selector,
  model/session/tree/fork/auth selectors, countdown/armin loader
  components, editor keybinding handlers. Reachable, if at all, only
  through PTY-level render tests and live play, not through FiveAM
  in-image calls.
- **cadr-server process machinery** (`rpc-process.lisp`, `radius.lisp`,
  `main.lisp`): the server runs as a child process
  (`rpc-child-reader-loop`, `handle-rpc-child-line`,
  `heartbeat-radius-*`); in-image tests see only the parent side.
  Matches cadr-server's tree-low 35.5%.
- **OAuth and network flows** (`cadr-ai/oauth/*`,
  `tool-manager.lisp` download/install, provider request paths):
  credential- or network-gated by design.
- **evals entry** (`cadr-evals/main.lisp`: `parse-eval-arguments`,
  `%eval-main`, `validate-*-result`): driven by
  `scripts/run-evals.sh`, not by FiveAM.

### Class B2: missed branches in tested functions (785 records)

The function runs but a specific decision never happens. Recurring
shapes, with examples:

- **Validator rejection paths**: the protocol and agent schema
  validators (`cadr-protocol/schema.lisp`, `cadr-agent/schema.lisp`)
  are fed only well-formed values; every `exact-object-keys-p` /
  `nonempty-string-p` / `one-of-string-p` rejection branch is zero.
  110 records in the two schema files alone.
- **Optional-field emitters**: JSON serializers in
  `cadr-cli/modes/print.lisp` never see messages carrying
  `thinkingSignature`, `redacted`, `addedToolNames`, `finalError`,
  `willRetry`, `steering`, etc.
- **Parser edge constructs**: mermaid (`parse.lisp`, `labels.lisp`)
  fixtures lack quoted labels, `<<stereotype>>`, `as` aliases, numeric
  HTML entities, `…` truncation at `+gm-max-members+`/`+gm-max-edges+`,
  sequence-note anchors.
- **Error guards**: `(error ...)` / `configuration-error` arms of
  argument and settings validation; also the one cadr-core record —
  `src/cadr-core/cancellation.lisp:67`, the external-predicate check
  after `condition-wait` in `wait-for-cancellation`: tests always
  abort through the latch before timeout, never through the predicate.
- **Host-dependent paths**: the tool-not-found / download path of
  `ensure-tool` (all tools present on this host), Termux/Android
  detection. Reachable with a manipulated `PATH`; not unreachable.

## Findings booked (conclusions)

1. The deterministic FiveAM suite drives 62.8% of instrumented branch
   ways (75.5% of expression marks). No threshold is set; this is the
   baseline number for future comparisons.
2. Eight dead functions (class A, 20 records) are booked above for a
   removal decision; they are not test gaps.
3. The largest untested surface is structural, not incidental:
   `cli-handler` (96 records), the llama extension (73+), interactive
   selectors, the cadr-server child-process machinery, and OAuth/
   network flows are all outside the deterministic suite's reach —
   covered, if at all, by credential-gated live tests and subprocess
   smokes that in-image coverage cannot see. Whether these need
   in-image drivers is a Part L/M scope question, not decided here.
4. Validator negative paths (`cadr-protocol/schema.lisp`,
   `cadr-agent/schema.lisp`, 110 records) are reachable with crafted
   malformed inputs and are the cheapest meaningful gap to close.
5. `cadr-core` is nearly clean: a single missed branch
   (`cancellation.lisp:67`, predicate-after-timeout path).

## sb-cover notes for the next operator (SBCL 2.6.7)

- The optimization quality is proclaimed
  `(optimize sb-cover:store-coverage-data)` — **without** inner
  parentheses; `(optimize (sb-cover:store-coverage-data))` is a
  malformed declaration that SBCL only warns about while producing no
  instrumentation.
- `sb-cover:enable-coverage-logging` must run before anything is
  compiled, or `covered-file-locations`/`-lines` stay nil and no
  line-level attribution is possible.
- There is no exported per-branch query API. `sb-cover:report` (HTML)
  and `sb-cover:lcov-report` are the only exported readers; this
  measurement used internals (`sb-c::*code-coverage-info*`,
  `sb-cover::get-records`, `sb-cover::refresh-coverage-bits`,
  `sb-cover::unpack-pair`), verified against the 2.6.7 contrib source
  and cross-validated against `lcov-report` output.
- `sb-cover:save-coverage-in-file` round-trips through
  `restore-coverage-from-file` without the code loaded (locations are
  lost; rebuild them from the sources with sb-cover's source-map
  reader — package-qualified symbols then require the production
  packages to exist in the image, so load the systems first).
- Branch record states: `#b1010` neither way taken, `#b1001`/`#b0110`
  one way, `#b0101` both; expression records are 1 (executed) / 2
  (not).
- Do not use `:force t` for the measurement: recompiling a file
  replaces its per-file record and silently zeroes marks already
  accumulated.
- A "top-level form called" flag can be derived mechanically: any
  executed record strictly below the toplevel path (the toplevel
  record itself executes at load and proves nothing).
